# tau2-bench, straight from upstream

`scripts/custom/run_tau2_bench.sh` runs [tau2-bench](https://github.com/sierra-research/tau2-bench) as upstream ships it, with nothing of ours in between: any tag, branch or commit of the repository (`--git-ref`, default `v2.0.0`), the dependencies upstream's own `uv.lock` pins, and every domain that ref has. At `v2.0.0` those are `mock`, `airline`, `retail`, `telecom`, `telecom-workflow`, `banking_knowledge` and `intake`. The defaults are tau2-bench's own, not a leaderboard's protocol.

```bash
scripts/custom/run_tau2_bench.sh --domain retail --model <served model> \
  --api-base-url "$EVAL_API_BASE_URL" --num-tasks 2
```

- **Install.** In the [prebuilt eval image](lm-eval-harness.md#prebuilt-evaluation-image-no-installs-at-run-time) upstream's checkout and its dependencies are baked in at the ref of `requirements/tau2-upstream.commit` (v2.0.0): nothing is installed or downloaded at run time, and `--git-ref` must name that ref or its commit (another ref, or `--repo`, is refused). Outside the image the ref is checked out into a cache keyed by its commit (`${EVAL_ENV_CACHE_ROOT:-$SCRATCH/eval-envs}/tau2-upstream`, `--cache-dir` to move it) and `uv sync --frozen --extra knowledge` installs it on Python 3.12 into the checkout's own `.venv`; that needs `git`, `uv` and network access the first time a commit is used. Our own lock does not come into it: upstream's `uv.lock` and the ref are the version. A bump of the image's tau2-bench is a change of `requirements/tau2-upstream.commit` (and so a new image).
- **Models.** The model under test is reached like `run_inspect_eval.sh` reaches its model (`--api-base-url`, key `TARGET_API_KEY`, else `CSCS_SERVING_API`). The key is never written into tau2's arguments: they carry `api_key: "os.environ/TARGET_API_KEY"` (litellm reads it at call time), so `results.json` and `--verbose-logs` hold no key. The simulated user is the same model on the same endpoint unless `--user-llm` says otherwise, at `reasoning_effort: low` with `max_tokens: 4096` (at the model's default effort a user turn sometimes ran 15k tokens and ended with no reply, which tau2 rejects and retries the whole task); `--user-llm-args` overrides both. A bare `--user-llm` name uses litellm's own credentials and gets neither. Sampling and thinking flags are the other launchers' (`--temperature`, `--top-p`, `--sampling-profile`, `--enable-thinking`, `--reasoning-effort`) and apply to the agent only (the user's effort is the pin above); tau2 sends no sampling setting unless you pass one.
- **The judge.** retail scores 112 of its 114 tasks partly with NL assertions (40 of them carry assertion text), which tau2 has an LLM check against the finished transcript. Upstream hardcodes that judge (`tau2/config.py`: `gpt-5.4-mini-2026-03-17`, at OpenAI, so it needs an `OPENAI_API_KEY`) and offers no option to change it. We have no such key, so with `--api-base-url` the judge is the model under test, at the same low effort and 4096-token cap as the simulated user (it judges its own runs: a bias, so retail scores are not comparable with published ones). `scripts/custom/tau2_judge/sitecustomize.py` does it, on `PYTHONPATH` of the `tau2` process: it replaces the evaluator's model and arguments in memory and touches no upstream file. A model is a worse fit than the one upstream was written for, so the shim also removes a markdown code fence around the judge's JSON (Chonk always adds one) and asks again, up to 8 times, when the reply does not parse or holds fewer verdicts than assertions (Chonk answers an empty list about half the time, which upstream would count as all assertions met); if it never gives a usable reply the evaluation raises, tau2 redoes the task, and nothing is scored without a judgement. Each retry prints a line. Without `--api-base-url` the judge stays upstream's own. airline, telecom and banking_knowledge do not use it.
- **Trials.** `--num-trials n` runs every task n times; the summary prints `avg_reward` and pass^k for k = 1..n (all k trials succeed, not pass@k). One trial is the default, so pass^1 is the plain mean.
- **Domain options.** `--retrieval-config` is banking_knowledge's retrieval pipeline. It defaults to `bm25` (keyword search, offline, free); tau2's own default embeds the documents with OpenAI and needs an `OPENAI_API_KEY`, which a job doesn't have. Banking scores with `bm25` are comparable between our runs, not with published tau2 numbers. Anything else goes after `--` to `tau2 run`, e.g. `intake` is voice-first, so a text run needs `-- --elicitation-strategy scaffolded`.
- **Results.** `<--workdir>/tau2-data/simulations/<--save-to>/results.json`: tau2 reads its data through a writable view in `--workdir` (the image is read-only), so give a `--workdir` on storage you keep when running in a job, since the container's `/tmp` is lost with it. The default run name is `<domain>-<date and time>`, a new run each time; the name of an earlier run resumes it, but only with the same domain, model and options.

`scripts/custom/` is for runners that do not go through one of the frameworks of this repository.

In a Slurm job: `sbatch scripts/custom/run_tau2_bench.sbatch <same arguments>` runs it CPU-only in the prebuilt image (or `containers/env.toml`) against an endpoint that is already serving, and without `--workdir` keeps the results in `logs/tau2/<job id>/`. [Suites](suites.md) launch their tau2 rows that way.
